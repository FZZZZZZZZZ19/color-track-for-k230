## 项目简介

本项目是一个运行在 **Canaan Kendryte K230** 芯片上的 **MicroPython 颜色追踪系统**。系统通过摄像头实时采集画面，识别特定颜色的物体，并通过 **PI 控制器** 驱动两个舵机（水平 Pan + 垂直 Tilt）组成的小型云台，使激光/摄像头始终对准目标物体。

### 核心特性

| 特性 | 说明 |
|---|---|
| 🎨 **LAB 色彩空间** | 使用 CIE L\*a\*b\* 色彩空间进行颜色检测，比 RGB/HSV 更接近人眼感知 |
| 🧮 **PI 控制器** | 比例-积分控制器，水平/垂直通道参数独立可调 |
| 📉 **低通滤波** | 一阶指数平滑滤波器，消除高频抖动 |
| 🚫 **死区控制** | 目标在中心附近时不驱动舵机，防止微小振荡 |
| 🔀 **积分分离** | 大偏差时关闭积分项，防止积分饱和（过冲） |
| 🔒 **积分限幅** | 积分项硬限幅，防止 windup |
| 📐 **双舵机云台** | 水平（Pan）+ 垂直（Tilt）独立控制 |
| 🔴 **激光指示** | GPIO 控制激光模块，追踪时常亮 |
| 🧠 **两种追踪策略** | 固定颜色追踪 / 形状引导自学习追踪 |

```
        摄像头视角（从后往前看）
```

## 两种追踪模式

`main.py` 文件包含 **两套独立的追踪程序**，请注意切换使用。

### 模式一：红色色块追踪

**代码位置**：[main.py:1-160](main.py)

#### 工作原理

1. 摄像头每帧进行 `find_blobs()` 调用，使用预设的 **LAB 红色阈值** 检测画面中的红色区域
2. 在所有检测到的色块中，选取 **面积最大** 的作为追踪目标
3. 计算目标中心与画面中心（320, 240）的像素偏差
4. 经过 **死区 → 低通滤波 → 积分分离 → PI 计算** 后输出舵机角度
5. 画面实时推送到 IDE 显示（`to_ide=True`）

#### 预设颜色阈值

```python
RED_THRESHOLD = (0, 80, 20, 80, 10, 80)
#                L_min, L_max, A_min, A_max, B_min, B_max
```

| 通道 | 范围 | 含义 |
|---|---|---|
| L (亮度) | 0 ~ 80 | 排除过亮区域（白色/反光） |
| A (红绿轴) | 20 ~ 80 | 正值 = 偏红 |
| B (黄蓝轴) | 10 ~ 80 | 正值 = 偏黄 |

#### 适用场景

- 追踪**纯红色**物体（红球、红色标记、红色激光点等）
- 目标颜色已知且固定
- 需要 IDE 实时预览

### 模式二：形状引导颜色学习追踪

**代码位置**：[main.py:162-349](main.py)

#### 工作原理

此模式分为 **两个阶段**：

##### 🔵 阶段一：颜色学习（LEARN）

```
┌──────────┐      ┌───────────┐      ┌──────────────┐
│ find_circles │──▶│ 取最大圆形   │──▶│ 提取ROI颜色统计│
│ 检测圆形物体  │    │ (按半径排序) │    │ mean±2*std   │
└──────────┘      └───────────┘      └──────┬───────┘
                                            │
                              ┌─────────────▼─────────────┐
                              │ 连续30帧成功 → 切换到TRACK  │
                              │ 任意帧失败 → 计数器归零重来  │
                              └───────────────────────────┘
```

1. 调用 `find_circles()` 检测画面中的圆形物体
2. 选取半径最大的圆形
3. 以圆心为中心，取 **1.2 倍半径** 的正方形 ROI
4. 调用 `img.get_statistics(roi=...)` 获取 ROI 内的 LAB 颜色统计量（均值、标准差）
5. 以 `mean ± 2.0 × stdev` 作为该颜色的 LAB 阈值
6. **连续 30 帧** 成功检测到圆形后，将学习到的阈值锁定，切换到追踪阶段

##### 🟢 阶段二：颜色追踪（TRACK）

```
┌──────────┐      ┌────────────────┐      ┌──────────────┐
│find_rects│──▶│ 逐个矩形ROI内     │──▶│ 第一个匹配的   │
│检测所有矩形│    │ find_blobs(学习  │    │ 色块作为目标   │
│          │    │  到的阈值)       │    │              │
└──────────┘      └────────────────┘      └──────┬───────┘
                                                 │
                                        ┌────────▼────────┐
                                        │ PI控制器 → 舵机   │
                                        └─────────────────┘
```

1. 调用 `find_rects()` 检测画面中所有矩形区域
2. 依次在每个矩形 ROI 内调用 `find_blobs()` 搜索匹配学习颜色的色块
3. 找到的第一个包含匹配色块的矩形即为目标
4. 对目标色块中心计算偏差，驱动 PI 控制器
5. **不向 IDE 传输图像**（`to_ide=False`），提高帧率

#### 关键配置

```python
LEARN_DURATION = 30        # 学习阶段需连续检测到圆的帧数
find_circles(threshold=3500, r_min=20, r_max=200)  # 圆形检测参数
find_rects(threshold=10000)  # 矩形检测阈值 (8000~15000)
scale = 2.0                # 颜色阈值扩展倍数 (mean ± 2σ)
```

#### 适用场景

- 目标颜色**未知或变化**（不同光照环境，不同颜色物体）
- 需要在**复杂场景**中追踪特定形状包围的色块
- 追求**高帧率**（不需要 IDE 预览）

## 控制算法详解

### 1. 死区（Dead Zone）

```python
DEAD_ZONE = 5  # 像素

if abs(offset_x) < DEAD_ZONE:
    offset_x = 0
```

| 参数 | 作用 | 调大 | 调小 |
|---|---|---|---|
| `DEAD_ZONE` | 中心容错范围 | 更稳定，但响应迟钝 | 更灵敏，但中心抖动 |

当目标距离画面中心在 ±5 像素以内时，视为"已对准"，不再驱动舵机，避免来回修正导致的"抽搐"。

---

### 2. 低通滤波（Low-Pass Filter / EMA）

```python
ALPHA = 0.11

filtered_offset = ALPHA * raw_offset + (1 - ALPHA) * filtered_offset
```

这是一阶 **指数移动平均（EMA）** 滤波器：

- `ALPHA` 越大 → 响应越快，但滤波效果减弱（更抖动）
- `ALPHA` 越小 → 越平滑，但响应延迟增大

```
ALPHA = 0.11 的含义：
  - 约 63% 的阶跃响应在 1/0.11 ≈ 9 帧内完成
  - 约 95% 的阶跃响应在 3/0.11 ≈ 27 帧内完成
  - @30fps → 约 0.3 秒达到 63%，约 0.9 秒达到稳态
```

---

### 3. PI 控制器

```
Output = Kp × error + Ki × ∫error
```

#### 独立通道参数

| 参数 | 水平(Pan) | 垂直(Tilt) | 说明 |
|---|---|---|---|
| P 增益 | `PAN_P_GAIN = 0.15` | `TILT_P_GAIN = 0.16` | 比例项：误差越大，输出越强 |
| I 增益 | `PAN_I_GAIN = 0.04` | `TILT_I_GAIN = 0.06` | 积分项：消除稳态误差 |

**为什么水平/垂直参数不同？**
- 云台的水平和垂直方向**转动惯量不同**（垂直方向受重力影响更大）
- Tilt 在克服重力时需要更强的积分来消除静差，因此 I 增益稍大

---

### 4. 积分分离（Integral Separation）

```python
I_SEPARATE_THRESH = 30  # 像素

if abs(filtered_error) < I_SEPARATE_THRESH:
    integral += filtered_error   # 小偏差：正常积分
else:
    integral = 0                 # 大偏差：清零积分
```

| 场景 | 积分行为 | 目的 |
|---|---|---|
| 偏差 < 30px（接近目标） | 正常累加积分 | 消除稳态误差，精确对准 |
| 偏差 > 30px（远离目标） | 积分清零 | 防止大偏差时积分过度饱和导致过冲 |

这是经典的 **积分分离 PI** 策略，解决了传统 PI 在大阶跃响应时的超调问题。

---

### 5. 积分限幅（Integral Clamping）

```python
integral_pan = max(-30, min(30, integral_pan))
integral_tilt = max(-30, min(30, integral_tilt))
```

将积分项硬限制在 [-30, 30] 范围内，作为**抗饱和（Anti-Windup）** 的最后一道防线。

---

### 6. 积分衰减（无目标时）

```python
# 没有找到色块时
integral_pan *= 0.95
integral_tilt *= 0.95
```

丢失目标后积分值**以 0.95 的速率逐帧衰减**，使舵机缓慢回到中心位置，而不是突然归中。

## 参数配置与调优

### 完整参数表

| 参数 | 默认值 | 范围 | 说明 |
|---|---|---|---|
| `PAN_P_GAIN` | 0.15 | 0.05 ~ 0.5 | Pan 比例增益 |
| `PAN_I_GAIN` | 0.04 | 0.01 ~ 0.1 | Pan 积分增益 |
| `TILT_P_GAIN` | 0.16 | 0.05 ~ 0.5 | Tilt 比例增益 |
| `TILT_I_GAIN` | 0.06 | 0.01 ~ 0.1 | Tilt 积分增益 |
| `ALPHA` | 0.11 | 0.05 ~ 0.5 | 低通滤波系数 |
| `DEAD_ZONE` | 5 | 2 ~ 20 | 死区像素 |
| `I_SEPARATE_THRESH` | 30 | 10 ~ 60 | 积分分离阈值(像素) |
| `RED_THRESHOLD` | `(0,80,20,80,10,80)` | LAB 空间 | 红色检测阈值(模式一) |

### 调参指南

#### 🎯 追踪振荡（来回摆动）

```
现象：舵机在目标附近来回摆动，不停"点头"
原因：P 增益过大 / 死区太小 / 滤波不够

解决（按顺序尝试）：
  1. 增大 DEAD_ZONE → 试试 8 或 10
  2. 减小 PAN_P_GAIN / TILT_P_GAIN → 试试 0.10
  3. 减小 ALPHA → 试试 0.06
```

#### 🐌 追踪迟钝（跟不上目标）

```
现象：目标移动后，舵机反应慢半拍
原因：P 增益太小 / 滤波太强

解决（按顺序尝试）：
  1. 增大 PAN_P_GAIN / TILT_P_GAIN → 试试 0.20 ~ 0.30
  2. 增大 ALPHA → 试试 0.20
```

#### 🎯 始终对不准（有固定偏差）

```
现象：舵机稳定但目标不在画面正中
原因：积分增益太小 / 存在稳态误差

解决：
  1. 增大 PAN_I_GAIN / TILT_I_GAIN → 试试 0.06 ~ 0.10
  2. 检查舵机是否安装有机械偏差
```

#### 🚀 过冲（超过目标再拉回来）

```
现象：舵机冲过头再往回拉
原因：P 增益过大 + 积分饱和

解决：
  1. 减小 I_SEPARATE_THRESH → 试试 20
  2. 减小 PAN_P_GAIN
```

#### 🔴 颜色检测不稳定

```
现象：时有时无地检测到色块
原因：颜色阈值不合适 / 光照变化

解决（模式一）：
  1. 在 IDE 中查看当前画面的 LAB 值
  2. 调整 RED_THRESHOLD 的六个参数

解决（模式二）：
  1. 增大 scale → 试试 2.5 或 3.0
  2. 确保学习时光照条件与追踪时一致
```

3. 上电进入**学习模式**
4. 将一个**圆形**彩色物体（如彩色小球）放入画面中
5. 等待约 1 秒（30 帧），系统自动学习颜色
6. 学习完成后系统输出：`学习完成！切换到追踪模式。阈值: (...)`
7. 将带有该颜色的**矩形物体**放入画面，系统开始追踪
8. 按 Reset 键重新上电可重新学习新颜色

## 常见问题

### Q: 舵机不动？

- 检查舵机**供电** — 推荐独立 5V/2A 电源
- 检查 GND 是否**共地**（K230 的 GND 和舵机电源 GND 必须连接）
- 确认 PWM 引脚映射正确（Pin 42 → PWM0, Pin 43 → PWM1）
- 用 `duty()` 函数手动测试舵机是否工作

### Q: 两个舵机同时抖动/抽搐？

- **供电不足**是首要原因，请使用独立电源
- 尝试增大 `DEAD_ZONE` 到 8 或 10
- 尝试减小 `ALPHA` 到 0.06

### Q: K230 板子反复重启？

- 舵机从 K230 取电导致电压跌落
- 必须使用独立电源给舵机供电
- 在舵机电源回路加一个 **470μF ~ 1000μF** 电解电容滤波

### Q: 颜色检测不到目标？

- **光照影响巨大** — 在目标光照环境下调整 LAB 阈值
- 确认摄像头的 Sensor ID — K230 有多个型号，可能需要改为 `Sensor(id=1)` 或 `Sensor(id=0)`
- 模式二中学生阶段要确保圆形物体清晰可见
- 尝试增大 `scale` 参数扩大颜色范围

### Q: find_rects() 检测不到矩形？

- 调整 `threshold` 参数（当前 10000，范围 5000 ~ 20000）
- 确保矩形区域有清晰的边缘（边缘不模糊、对比度足够）
- 矩形不能太小（隐式限制：需要有足够面积容纳色块）

### Q: 如何切换程序一和程序二？

- 默认运行程序一（红色追踪）
- 要运行程序二：注释或删除第 1-160 行（含第 160 行的"形状匹配"），保留第 162 行之后的代码
- 注意两套程序互相独立，不要混合使用

### Q: 如何调试新的目标颜色？

可以在 CanMV IDE 的 REPL 中使用以下代码查看当前画面的 LAB 统计信息：

```python
import time
from media.sensor import *
from media.display import *
from media.media import *

sensor = Sensor(id=2)
sensor.reset()
sensor.set_framesize(width=640, height=480)
sensor.set_pixformat(Sensor.RGB565)
Display.init(Display.VIRT, width=640, height=480, to_ide=True)
MediaManager.init()
sensor.run()

while True:
    img = sensor.snapshot()
    stats = img.get_statistics()
    print(f"L: {stats.l_mean():.0f}±{stats.l_stdev():.0f}  "
          f"A: {stats.a_mean():.0f}±{stats.a_stdev():.0f}  "
          f"B: {stats.b_mean():.0f}±{stats.b_stdev():.0f}")
    time.sleep_ms(500)
```

## 技术参数速查

| 参数 | 值 |
|---|---|
| 主控平台 | Canaan K230 (RISC-V 64 位双核) |
| 固件类型 | MicroPython |
| 摄像头分辨率 | 640 × 480 |
| 像素格式 | RGB565 |
| 色彩空间 | CIE L\*a\*b\* |
| 帧率 | ~25-30 FPS（模式一，开 IDE）/ 更高（模式二，关 IDE） |
| 舵机频率 | 50 Hz（周期 20ms） |
| 舵机行程 | -90° ~ +90°（180° 范围） |
| 舵机映射 | 角度 → 占空比: `(angle+90)/180×10+2.5` |
| 控制器类型 | PI（比例-积分），积分分离式 |
| 滤波器类型 | 一阶指数移动平均（EMA） |
| 激光控制 | GPIO 输出，高电平常亮 |
